# iOS 汇总小组件与体力回满提醒

0.1.14，2026-10-18。使用原生 WidgetKit + SwiftUI 小组件和 UserNotifications 本机通知。iOS 最低版本调整为 14；iOS 17 及以上适配小组件容器背景。Android、鸿蒙、Windows 的系统小组件与通知不在本次范围。

## 使用

1. 在栖游连接账号并刷新游戏数据。
2. 打开“设置 → 小组件与体力提醒”，选择要显示的游戏。默认全选，但仅展示已连接且没有被移除的游戏。
3. 在 iOS 主屏幕添加“栖游 → 所有游戏”，选择小号、中号或大号。小号使用图标、体力和签到符号紧凑展示当前支持的七款游戏，中号增加游戏名称，大号增加回满时间和签到说明。文字使用内置鸿蒙黑体，图标复用已记录来源的官方 PNG。
4. 主动开启“体力回满提醒”，允许 iOS 通知权限。被拒绝时可从页面进入系统设置；打开应用或小组件不会自动弹通知授权。

同一款游戏多个角色汇总为体力/容量之和；有角色未同步时显示待刷新，全部角色当天签到成功才显示对勾。部分完成、待签到、需要处理和未知状态分别显示不同符号。签到日使用北京时间；跨日时间线会把昨天的已签改为待刷新，不当作今天已签。小组件展示最近查询值，不按时间臆造当前体力；满体力时间只显示预测。超过六小时的数据显示待刷新。

游戏页筛选不影响小组件范围。设置中的游戏选择只控制小组件，不影响游戏页和体力提醒；在游戏详情移除游戏则同时停止其查询、签到与待发通知。切换到演示空间时清空真实摘要并撤销提醒，不为演示数据安排通知。退出演示后重新刷新。

## 通知边界

提醒按单个角色的官方 recoverySeconds 或现有适配已经解析出的官方回满时间，在最近同步时间上计算绝对截止时间。仅为数据有效、查询成功、同步时间不超过六小时、体力未满且回满时间在未来七天内的角色安排一次通知。多个账号的标识使用散列，不在通知或共享区保存原始 UID、账号编号和昵称。最多保留最早的 60 条待发提醒。

刷新成功时替换同标识的旧通知；查询失败、移除角色或关闭开关时撤销相关待发通知。已回满不重复安排即时通知。通知文案明确为“预计已回满”，因为在游戏里消耗体力后，应用无法自行获知：请回到栖游刷新，更新提醒时间。缺少官方回满时间的游戏暂不安排通知，包括目前尚未返回这项数据的接口；不凭经验猜恢复速率。

不运行后台自动签到，不把认证信息交给小组件，也不保证后台持续联网。WidgetKit 按系统预算决定实际更新时间，通知可能受专注模式、摘要和系统设置影响。小组件通过应用写入共享快照并请求重载；时间线在预计回满、数据过旧和北京时间午夜等节点更新显示，不发起真实账号请求。参照 [Apple 小组件刷新说明](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date) 和[本地通知](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app)。

## 签名与共享区

主应用 `app.qiyou.qiyou` 和扩展 `app.qiyou.qiyou.QiyouWidget` 都启用 App Group `group.app.qiyou.qiyou`。正式安装需要在自己的 Apple Developer 团队中注册这两个标识及共享组，两个 target 使用同一团队并包含对应授权描述文件。更换 bundle ID 时同步修改两个 entitlements、共享 Swift 常量以及 target 配置中的标识。GitHub Actions 输出未签名 app，不能代替真机签名配置。参照 [Apple App Groups 配置](https://developer.apple.com/documentation/xcode/configuring-app-groups)。

共享文件 `qiyou-widget-v1.json` 只包含游戏枚举、角色数量、汇总体力、签到状态和时间戳，原子写入并采用首次解锁后的文件保护。Cookie、访问/刷新令牌、设备标识、WebDAV 凭据与原始账号数据继续保存在原有安全存储，不写入共享组。小组件设置与通知开关仅保存在本机，不随 WebDAV 同步，也不替其他设备请求权限。

## 验证

`test/ios_companion_test.dart` 覆盖七游戏汇总、隐私字段、筛选隔离、多个角色的部分签到/查询失败、未知/过期/已满数据、通知数量限制、权限、设置保存与回滚、移除游戏、桥接故障恢复和亮暗窄屏设置。`ios/CompanionCore` 的 Swift 测试覆盖快照校验、北京时间跨日、过旧数据、时间线节点和通知标识/截止时间。

macOS Actions 编译模拟器和未签名真机 app，核对扩展、字体与图标嵌入，运行原生通知截止时间测试，并为三个尺寸、较小屏幕和自选游戏状态渲染亮暗截图。界面测试位于 `ios/WidgetPreviewHost/WidgetTests.swift`，独立 SwiftUI 预览程序复用生产小组件界面和原始资源，避免为截图启动 Flutter 或读取社区账号；该测试程序不会嵌入发布 App。真实 iPhone 添加小组件、通知送达、专注模式和签名后的共享组访问仍需真机验收。

2026-10-18，0.1.14（build 15）[Actions 验证通过](https://github.com/hanyin111/qiyou/actions/runs/39111665673)：Dart 120 项、Swift 数据 6 项、原生系统/界面 2 项。覆盖小号七游戏、更小尺寸七游戏、自选三款、自选一款、中号、大号共 12 张亮暗截图；检查了实际彩图像素及字体资源，并逐张视觉核对。0.1.13 预览暴露的图标未绘制和文字省略问题已修正为直接 UIKit 图像加载及自适应排版。

iOS 发布包已校验版本、七款图标、两款原始字体及许可、扩展可执行文件和 ZIP 完整性；测试宿主没有嵌入发布包。Windows、Android 和 Web 构建也通过，本次没有执行鸿蒙构建。之前完整 Flutter App 作为 XCTest 宿主时在用例执行前异常退出，因此原生截图使用独立预览程序；这些通过结果不能替代完整 App 的真机登录和通知送达验收。
