# 0.1.17：短信登录验证码白屏修复

用户在 0.1.16 的 iPhone 上确认：已有米游社账号的体力安全验证可以加载并通过；新增米游社、库街区短信登录中的安全验证页保持空白。本次只修复短信登录验证码，不改动已能通过的体力验证、已保存账号或包名。

## 原因和修复

在 `about:blank` 中运行原登录验证页与真实极验 v4 SDK，实际观察到后续请求变成 `about://gcaptcha4.geetest.com/load`，备用服务器和脚本也继承错误协议，被页面安全策略阻止。原配置缺少 v4 的 `protocol`。同样的页面仅加上 `protocol: "https://"` 后，出现 `ready` 回调和可见的“点击按钮开始验证”按钮。极验[官方配置文档](https://docs.geetest.com/gt4/apirefer/api/web#protocol)明确要求本地或混合应用手动设置协议。

生产登录页现在固定 v4 的 HTTPS 协议；v3 保留原来的 `https: true`。保留官方脚本与必要资源的域名限制，兼容 SDK 使用的备用资源域名。脚本放入独立作用域，初始化函数缺失、脚本异常、资源失败、超时均返回有限的错误类别，不传递原始异常、网址或验证内容到诊断日志。页面有加载文字与失败提示。

WebView 先安装回调，再加载本地文档。Flutter 页面提供“重新加载”，每次更换随机绑定值并忽略旧回调；重新加载验证码不会发送短信或重做登录。只有用户验证成功且证明字段通过校验后，才交回原短信请求流程。手机号、短信码、账号 Cookie 均不进入此页面。

## 验证方式

本地静态检查通过，137 项 Flutter 测试通过，新增米游社 Aigis v4（没有 v3 challenge）解析和证明绑定测试。隔离 Chromium 的五项执行检查通过：v3/v4 的延迟桥接、可见组件、合成手动回调，以及各自的脚本加载失败；第五项使用真实公开 v4 SDK 与库街区公开站点标识，仅加载按钮，不完成或提交验证。

`dart run scripts/export_login_captcha.dart` 从生产代码导出不含账号的测试文档。iOS 独立原生测试宿主读取同一份文档，以插件实际使用的 `WKWebView.load(data, ..., baseURL: about:blank)` 入口测试真实公开 SDK 的 `ready`、可见组件尺寸和顶层导航策略；另用系统内容规则阻断 SDK，确认 v3/v4 都返回失败而非保持空白。该宿主和测试文档不进入安装包。
